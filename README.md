Diplom_2 - API-тесты Stellar Burgers
О проекте

Этот репозиторий содержит автоматические API-тесты для сервиса Stellar Burgers в рамках второго задания дипломного проекта по автоматизации тестирования.
Тесты покрывают основные сценарии работы публичного API сервиса и могут использоваться как часть регрессионного набора.

Технологии

Python 3.13

pytest — фреймворк для запуска автотестов

requests — отправка HTTP-запросов к API

allure-pytest — формирование наглядных отчётов о прогоне тестов

Все необходимые зависимости указаны в файле requirements.txt.

Установка и запуск
1. Установка зависимостей

Из корня репозитория выполните:

pip install -r requirements.txt


Убедитесь, что команда выполняется тем интерпретатором Python, который вы используете для запуска тестов.

2. Запуск тестов

Запустить все тесты с подробным выводом в консоль можно командой:

pytest -v


По умолчанию будут прогнаны все тесты из папки tests.

3. Генерация отчёта Allure

Для генерации отчёта Allure выполните:

pytest -v --alluredir=allure-results


Результаты прогона будут сохранены в директорию allure-results.

Для локального просмотра отчёта (при установленном Allure и добавленном в PATH) можно использовать:

allure serve allure-results


После выполнения команды откроется браузер с интерактивным отчётом: дерево тестов, шаги, статусы, вложения.

Основные сценарии, покрытые тестами

Тесты сгруппированы по функциональным областям: создание пользователя, авторизация пользователя, создание заказов.

Создание пользователя

Тесты для эндпоинта регистрации проверяют:

успешное создание нового уникального пользователя;

попытку повторной регистрации уже существующего пользователя (ошибка и корректное сообщение);

попытку создания пользователя без одного из обязательных полей (email, password или name) и корректную обработку такой ситуации.

Для генерации уникальных пользователей используется вспомогательный код, чтобы тесты были независимыми и могли запускаться многократно.

Авторизация пользователя

Тесты для авторизации проверяют:

успешный логин уже зарегистрированного пользователя с корректными учётными данными;

логин с неверным логином/паролем и возврат соответствующей ошибки и сообщения от сервера.

Создание заказов

Тесты для создания заказов проверяют:

создание заказа авторизованным пользователем с валидным набором идентификаторов ингредиентов;

создание заказа без авторизации (гостевой заказ);

попытку создания заказа без ингредиентов;

попытку создания заказа с некорректным идентификатором ингредиента.

Для получения валидных идентификаторов ингредиентов используется отдельный запрос к эндпоинту /api/ingredients, после чего тесты подставляют реальные id в запрос на создание заказа.

Проект структурирован так, чтобы код, отвечающий за работу с API (клиент, данные, эндпоинты), был вынесен в отдельные модули, а сами тесты оставались максимально читаемыми и отражали бизнес-сценарии, описанные в задании диплома.
